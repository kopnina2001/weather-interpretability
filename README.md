# Интерпретация моделей прогноза погоды

Репозиторий содержит интервенционный аудит Aurora и Pangu-Weather. В одном
входном поле фактическое состояние заменяется климатологией WeatherBench 2, а
остальные поля, дата и веса модели остаются прежними. Разность между базовым и
измененным прогнозами показывает, как модель переносит входное возмущение между
выходными полями.

Основной результат — направленные матрицы отклика размером 19x19 для сроков +6 и
+24 ч. Это характеристики обученных операторов прогноза, а не причинные связи в
атмосфере.

## Эксперимент

### Данные

- ERA5: начальные состояния и верификация;
- WeatherBench 2: климатология по дню года и часу UTC за 1990–2019 годы;
- основная выборка: 48 инициализаций 2024 года, по четыре даты в месяц;
- дополнительная проверка Aurora по семи полям: 48 дат из 2024–2025 годов.

В основной матрице используются 19 полей: MSLP, U10, V10, T2M и пять полей
`Z/Q/T/U/V` на уровнях 1000, 850 и 500 гПа. `Z` хранится как геопотенциал в
м²/с², а не как геопотенциальная высота.

### Модели

| Модель | Вход | Сетка | Реализация |
|---|---|---|---|
| Aurora 1.3B | два состояния, `t-6 ч` и `t` | 0.25°, 720 широт после crop | PyTorch |
| Pangu-Weather 256M | одно состояние `t` | 0.25°, 721 широта | ONNX |

У Aurora выбранное поле заменяется в обоих входных состояниях. Pangu запускается
шагами по 6 ч до нужной заблаговременности.

### Метрики

Для входного поля `v`, выходного поля `u` и срока `tau` считаются:

```text
S_vu(tau) = RMSE_w(patched, baseline) / sigma_w(truth)
dACC_vu   = ACC_w(patched, ERA5) - ACC_w(baseline, ERA5)
```

Пространственные метрики используют нормированные веса `cos(latitude)`. `S`
измеряет сдвиг относительно неизмененного прогноза; отрицательное `dACC`
показывает потерю верифицированного качества аномалий. Уменьшение диагонального
`S` означает возврат к базовой траектории, но само по себе не доказывает
исправление относительно ERA5.

Дозовый эксперимент заменяет `Z1000` по сетке
`alpha = {0, 0.2, 0.4, 0.6, 0.8, 1}`. Пространственные композиты считают
временную RMSE отдельно в каждом узле. Приведенные для них «глобальные» отношения
— средние по узлам сетки без площадного взвешивания.

## Подтвержденные наблюдения

- Матрицы отклика несимметричны. На +6 ч замена `Z850` заметно сильнее меняет
  прогноз `V850`, чем замена `V850` меняет прогноз `Z850`, в обеих моделях.
- Диагональный отклик `Z500` уменьшается между +6 и +24 ч, тогда как часть
  внедиагонального переноса сохраняется.
- Возмущение нижнего геопотенциала влияет на температуру, влажность и ветер.
  Объяснение через рельеф и экстраполяцию ниже поверхности пока не отделено от
  вертикальной связи.
- Отклик `T1000` на замену `Z1000` ослабевает с заблаговременностью у Aurora,
  но усиливается у Pangu. Универсальной самокоррекции всех полей нет.
- Карты показывают разные широтные профили добавленной ошибки. Они задают
  кандидатов для проверки отдельных весов полей и широт, но не доказывают, что
  такие веса улучшат обучение.

Числа в статье сейчас являются точечными оценками. Исходные массивы и метрики
хранятся вне git; на машине без `/srv/exw` их нельзя независимо пересчитать.

## Структура репозитория

```text
experiments/
  campaign/       базовая верификация моделей
  patching/       полная замена одного из 19 входных полей
  dose_response/ плавная замена Z1000
analysis/         расчет матриц, сравнений и интервалов
plots/            построение матриц, кривых и пространственных композитов
figures/          сохраненные иллюстрации
paper/            текущая русская и английская статья
report/           методика метрик и архивный отчет
legacy/           эксперименты вне текущей статьи
```

Тяжелые данные подключаются символьными ссылками:

```text
data: символьная ссылка на внешний каталог исходных данных
results: символьная ссылка на внешний каталог результатов прогонов
```

## Воспроизведение основных таблиц

После подключения внешних каталогов:

```bash
python analysis/compute_19var_matrix.py aurora
python analysis/compute_19var_matrix.py pangu

python analysis/compare_models_19var.py

python analysis/bootstrap_19var.py \
  --n-bootstrap 5000 \
  --output-dir results/patching/patching_19var/bootstrap
```

`compare_models_19var.py` по умолчанию читает `rel_sens_w` и `dacc_w`. Флаг
`--unweighted` оставлен только для сопоставления с ранними расчетами.
`compute_19var_matrix.py` также сохраняет `delta_rmse_w_anom` — добавочную RMSE
патченного прогноза относительно ERA5, нормированную на СКО аномалии.

Блочный bootstrap пересэмплирует календарные месяцы, сохраняет четыре даты
внутри месяца и использует одну и ту же выборку для Aurora и Pangu. Он пишет:

- `weighted_matrix_ci.csv` — оценку и 95% интервал каждого элемента матрицы;
- `key_results_bootstrap.csv` — межмодельную корреляцию, асимметрию
  `Z850/V850`, затухание диагонали `Z500` и, после пересчета метрик,
  truth-relative изменение ошибки `Z500`.

## Что еще требуется перед подачей

1. Запустить bootstrap на исходных метриках и заменить точечные утверждения в
   статье оценками с 95% интервалами.
2. Проверить «самокоррекцию» по дополнительной ошибке относительно ERA5, а не
   только по расстоянию до базового прогноза.
3. Повторить ключевые интервенции с маской точек ниже поверхности или по
   высотным поясам рельефа.
4. Добавить реалистичный контроль: аномалию другой даты того же сезона и UTC или
   масштабированную аномалию той же энергии.
5. Проверить несколько ключевых пар на независимых датах 2025 года для обеих
   моделей.

Вероятностные модели, переобучение с новыми весами и подстановка ERA5 внутри
rollout остаются следующими экспериментами. Они не нужны для воспроизведения
текущих матриц.

## Окружение

Зависимости перечислены в `requirements.txt`. Для Aurora на V100 32 ГБ
используется `batch=1`, `torch.autocast(..., dtype=torch.float16)` и ручной
rollout через `model.forward()` с `_advance_batch()`. Pangu требует
`onnxruntime-gpu` и доступных CUDA-библиотек.
